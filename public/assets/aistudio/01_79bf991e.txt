# 报告摘要

本报告旨在回答一个产品决策问题：GlobalCodeTrans V2.0 应优先服务哪些中小企业用户、处理哪些跨境业务文件、识别和保留哪些专业信息对象，才能以有限的研发资源形成可验证的商业价值。

核心结论：GlobalCodeTrans 不宜定位为“全专业工程图自动重建软件”，也不宜只围绕学术论文公式识别展开。更合理的定位是：面向中小企业跨境投资、收并购、工程合作及设备进出口的专业技术文档翻译与保真处理平台。

* 首期核心用户：设备贸易/进口企业、工业项目投资方、制造业收购或合资方；工程承包商和专业服务机构作为重要扩展用户。
* 首期高价值资料：设备说明书、技术规格书、参数表、安装/接线图、检验报告、可研技术附件、资产设备台账、维护记录、工艺流程图。
* 首期优先对象：表格与参数、原文版面和图形保真、流程关系、图中文字定位翻译、设备/安装/接线图；曲线数据提取和公式结构重建作为专项能力逐步增强。
* 复杂 CAD、复杂三维模型、所有行业图纸的全自动结构重建，不应列入首期承诺。无法可靠识别时，保留原始图形并明确标记，不推测补造。
* 研发策略：复用成熟开源解析和识别项目，GlobalCodeTrans 自主负责专业工作流、术语和标准语境、引擎调度、结果核验及可交付文档。

# 研究方法、证据等级与限制

本报告采用公开资料桌面研究、国际贸易和制造业资料、标准组织公开目录、典型业务流程推导等方法。研究范围以中国、美国、德国、日本、韩国及欧盟为主要技术资料来源，以东盟（尤其老挝及周边市场）作为重点业务落地验证区域。

| 证据等级 | 含义 | 本报告使用方式 |
| :--- | :--- | :--- |
| A｜公开权威资料 | WTO、UNIDO、ISO、IEC、欧盟法规、政府贸易指南等 | 用于确认贸易规模、标准范围、法定技术文件和业务资料要求 |
| B｜行业业务资料 | 尽调清单、设备资料包、项目可研指南、行业实践资料 | 用于推导典型业务文件组合和风险点 |

# 一、目标市场与产品边界

## 1.1 目标用户定义

目标用户不是所有需要翻译的人，而是缺少大型企业内部技术翻译团队、专业文档工程团队或长期外包预算，却需要理解和交换跨境技术资料的中小企业及专业服务机构。典型用户包括：

* 跨境设备贸易商、进口商、经销商和设备使用企业；
* 工业项目投资方、项目公司、产业园及工厂投资者；
* 制造业、矿业、能源及基础设施项目的收购方、合资方；
* 中小型工程承包商、设备安装商、机电和专业分包商；
* 工程咨询、检测、尽调、投资顾问及专业服务机构。

## 1.2 产品不做什么

本产品不替代设计院、专业 CAD/BIM 软件、法定认证机构、律师或工程师签章。它的目标是提高专业文件跨语言理解、信息保真、资料审查和交付效率。对于影响安全、合规、工程尺寸、设备选型或交易估值的关键内容，软件应提供来源定位和人工复核机制。

## 1.3 目标市场链条

| 市场角色 | 代表国家/地区 | 在文档链条中的作用 |
| :--- | :--- | :--- |
| 技术与设备来源 | 中国、美国、德国、日本、韩国、法国、英国、意大利、瑞士 | 设备制造、工艺技术、技术标准、产品资料和检测文件的来源 |
| 标准与规范来源 | ISO、IEC、ASTM、ASME、API、NFPA、EN及国家采用标准 | 提供跨国可复用的术语、符号、制图和安全规则 |
| 项目落地市场 | 老挝、越南、泰国、柬埔寨、印尼等东盟市场；并关注中东、非洲和中亚 | 形成进口、投资、建设、运营和当地合规文件需求 |
| 中间服务机构 | 工程咨询、律师、审计、检测、认证、项目管理机构 | 帮助中小企业完成专业判断和交易/工程交付 |

产品市场逻辑：同一份设备文件可能由中国制造商编制，采用 IEC/ISO 或欧洲标准，最终提交给老挝进口商、项目业主或当地主管部门。系统必须识别“文件语言、制造国、标准体系、使用国”是不同维度，不能只按语言选择术语。

## 2.2 跨国共用的标准与图形语言

| 标准/体系 | 主要覆盖对象 | 对软件的直接意义 |
| :--- | :--- | :--- |
| ISO 128 系列 | 技术产品文件、工程图表达、线型、视图、剖面 | 识别线型、视图、剖面及技术图纸的通用表达 |

## 2.3 国家标准不是语言标签

产品应将标准体系作为独立元数据管理。至少区分：文件原始语言、文件来源国、设备制造商国家、适用标准编号及版本、项目实施国、目标翻译语言。相同的“压力”“额定功率”“接地”“安全阀”等词，在不同专业和标准语境中可能有不同的译法或技术边界。

# 三、中小企业跨境业务与典型文件资料包

## 3.1 设备进出口：高频、标准化、可验证

典型流程：询价与技术选型—技术澄清—合同/订单—制造与出厂检验—运输与报关—安装调试—培训与维护。贸易文件与技术文件并存，但专业翻译的高价值部分主要集中在技术规格、设备说明书、图纸、检验和运维资料。

| 业务阶段 | 常见文件 | 常见信息对象 | 主要风险 |
| :--- | :--- | :--- | :--- |
| 询价/选型 | 产品目录、报价单、技术规格书、数据表 | 型号、参数表、性能曲线、外形图 | 型号/参数误读导致错选 |
| 合同/采购 | 采购合同、技术协议、偏差表、供货范围 | 条款表格、设备清单、接口条件 | 供货边界、性能保证理解错误 |
| 制造/出厂 | 检验报告、测试报告、材质证明、合格证 | 检测数据表、曲线、证书编号 | 检验指标、材料牌号、单位误译 |
| 进口/交付 | 商业发票、装箱单、原产地证、运输单证 | 商品名称、数量、型号、包装信息 | 单证不一致、清关资料错误 |
| 安装/运行 | 安装图、接线图、操作维护手册、故障表 | 尺寸图、电气图、步骤图、参数表 | 安装、接线、操作和安全风险 |

老挝进口和出口文件公开指南列举了发票、装箱单、原产地证以及特定商品许可或产品证明等要求；具体货物仍应按海关、主管部门和商品类别核验。欧盟机械法规（EU）2023/1230对机械技术文件、符合性声明、装配说明及相关图纸/图表作出要求，说明设备跨境流通中技术资料并非可有可无。

中小企业收购制造工厂、矿山或生产线时，通常需要把卖方提供的资产、运营、维护、产能、质量、安全环保和许可资料拼接起来。技术尽调的核心不是重建整套工厂图纸，而是验证影响交易价值的关键假设：实际产能、设备状态、剩余寿命、能耗效率、持续资本开支、扩产条件及合规缺口。

## 3.4 工程承包与项目实施

工程承包商通常接收业主、设计单位、总包商和设备供应商提供的规范、图纸、技术交底、材料报审、安装手册、检验与验收资料。其痛点是尺寸、单位、施工顺序、接口条件和验收要求的误解。软件首期应优先做到图纸和标注保真、文字定位翻译、表格结构保留，而不是擅自重绘施工图。

## 3.5 专业服务机构

工程咨询、检测、投资顾问、律师和项目管理机构可能需要处理多个客户、多个国家和多个行业的资料。它们对批量处理、术语库、版本管理、引用定位、审查记录和交付格式的要求更高，也可能成为软件的专业渠道用户。

## 4.1 用户共性与差异

五类用户的共同需求是：多语言文件读取、术语和标准编号保留、数值/单位准确、表格结构保留、图形不丢失、图中文字可定位、译文可追溯、输出可交付。差异在于：设备贸易商重参数和安装；投资方重技术方案和成本；收购方重资产/运营证据链；工程承包商重尺寸和施工要求；专业服务机构重批量、审查和版本管理。

## 4.2 用户并不需要“所有图都能编辑”

对多数中小企业用户，优先价值是读得懂、对得上、查得到、交得出去。复杂工程图只要准确保留原图、定位关键标注并翻译相关文字，已经能解决一部分高频问题。可编辑重建应是有条件的能力，而不是所有对象的强制目标。

# 五、图形、表格和专业对象的需求优先级

## 5.1 高频对象定性排序

| 对象 | 典型来源文件 | 定性频率判断 | 跨行业复用 | 建议处理方式 |
| :--- | :--- | :--- | :--- | :--- |
| 参数表/设备规格表 | 说明书、技术协议、报价附件、检验报告 | 极高 | 极高 | 优先保留行列/合并单元格/单位/数值/表头 |
| 表格化清单/台账 | 设备清单、资产台账、材料表、工程量清单 | 极高 | 极高 | 结构化提取、字段对齐、双语输出 |
| 流程图/工艺流程图 | 可研、生产工艺、设备资料 | 高 | 高 | 识别节点、箭头、连接关系；先保真后重建 |
| 平面布局/设备布置图 | 可研、厂区规划、安装文件 | 高 | 高 | 保留原图、定位文字/尺寸/图例 |
| 电气单线图/接线图 | 设备安装、电力和运维资料 | 高 | 中高 | 符号与连线保真，图中文字翻译 |
| 外形/安装/机械结构图 | 说明书、采购技术附件 | 高 | 中高 | 保留矢量或高清原图，尺寸标注严格保护 |
| 统计图/趋势图/性能曲线 | 检测报告、可研、设备手册 | 中高 | 高 | 提取坐标轴、单位、图例和曲线；必要时数字化 |
| PFD/P&ID、液压气动图 | 化工、矿业、能源、水处理、机械 | 行业高频 | 中 | 先识别符号、标签、连接关系；专项扩展 |
| 复杂数学公式 | 论文、标准、计算书、技术报告 | 场景性高 | 中 | 先减少误检，再做结构识别和 OMML 输出 |
| 复杂CAD/三维/仿真图 | 设计交付、专业工程报告 | 场景性/专业性高 | 低至中 | 首期不承诺自动重建，保留原始对象 |

说明：频率等级是针对目标用户典型资料包的业务研判，不是对 PDF 页数、图形数量或市场规模的统计。一个设备参数表可能比一张复杂工程图更频繁地出现在报价、采购、验收和资产资料中。

## 5.2 六类通用图形能力

| 通用能力 | 需要识别/保护的要素 | 对应行业/场景 |
| :--- | :--- | :--- |
| 表格结构 | 行列、合并单元格、表头层级、单位、数值、脚注 | 所有目标行业 |
| 流程关系 | 节点、箭头、方向、分支、连接、标签 | 制造、化工、能源、项目管理 |
| 空间布局 | 位置、尺寸、标高、坐标、通道、相对关系 | 工厂、建筑、矿区、能源项目 |
| 符号与连接 | 电气、机械、液压、管道、仪表符号及连接 | 设备、电力、化工、机电 |
| 曲线与数据 | 坐标轴、刻度、单位、图例、数据点、曲线 | 设备性能、检测、能源、可研 |
| 几何与尺寸 | 线型、视图、剖面、尺寸、公差、基准符号 | 机械、建筑、土木、设备安装 |

## 5.3 首期能力优先级

*图5 首期能力优先级指数。指数为产品规划判断，不是市场调查或技术准确率。*

建议将表格/参数、PDF原文和版面保真、设备技术资料、流程图、图中文字定位翻译作为第一批能力。曲线数据提取和公式结构重建作为第二批专项能力。复杂 CAD 自动重建暂缓。

## 5.4 为什么公式不是唯一核心

公式是专业文档的重要对象，但在目标用户的设备贸易、投资、收购和工程资料中，参数表、清单、流程图、安装图、接线图、检验报告可能更普遍。公式识别仍需整改当前系统的误检和边界问题，但产品首期商业价值不应完全押注公式重建。

# 六、产品需求与系统功能建议

## 6.1 首期产品定义

建议定位：面向中小企业跨境投资、收并购、工程合作及设备进出口的专业技术文档翻译与保真处理平台。产品的核心承诺应是“专业信息尽量不丢失、关键数据可核对、无法确认明确提示”，而不是“任何工程图都可自动编辑重建”。

## 6.2 建议功能分层

| 层次 | 功能 | 首期要求 |
| :--- | :--- | :--- |
| 文件接入 | PDF、扫描PDF、Word、图片；批量任务与文件清单 | 支持常见文件；识别文件类型和页面质量 |
| 内容解析 | 文本、表格、图片、矢量对象、页面坐标、阅读顺序 | 保留原始来源和坐标；不将图像误判为文本 |
| 翻译与术语 | 专业翻译、术语库、标准/型号/单位保护 | 数值、单位、型号、标准编号可审查 |
| 对象处理 | 表格、流程图、布局图、接线图、曲线、公式 | 按对象类别选择原生提取/结构化重建/原图保留 |
| 质量控制 | 原文/译文对照、缺失项、低置信度标记、人工复核 | 禁止无证据 PASS；关键对象可追溯 |
| 输出交付 | Word、PDF、双语对照、附件索引 | 页面对应、图表不丢失、输出可打印和归档 |

## 6.3 图形处理分级原则

| 等级 | 处理方式 | 适用对象 | 质量原则 |
| :--- | :--- | :--- | :--- |
| A｜原生结构提取/重建 | 抽取结构数据并生成可编辑对象 | 文本、表格、公式、部分标准化图表 | 结构与数值须经验证 |
| B｜矢量/结构化图形重建 | 转换为 SVG/EMF/DXF 等可缩放对象 | 常见流程图、部分曲线和简单示意图 | 几何关系和连接关系不得改变 |
| C｜原始对象保真保留 | 保留原始 PDF 矢量或高清图像，定位并翻译外围文字/图中文字 | 复杂工程图、低质量扫描图、无法可靠识别对象 | 不推测、不补造、不擅自改动原图 |

## 6.4 关键质量控制规则

* 原始 PDF 是事实来源；不得根据常识推测原图中不存在的线条、尺寸、数值或结构。
* 原生 PDF 文本/矢量对象优先提取；只有原生信息不足时才使用 OCR 或视觉模型。
* 数值、单位、型号、标准编号、图号、页码、设备位号应设置保护和核对机制。
* 无法可靠识别的区域应保留原图并标记“待人工核验”，不能自动补全。
* 公式识别置信度必须由结构特征和实际验证支撑；不能仅凭字母数字、数学符号或正则表达式判定。
* 验收必须调用真实模块并处理真实样本；代码存在、依赖声明、编译通过或模拟 PASS 均不等于功能通过。
* 报告和输出应保留页码、区域坐标、原始对象来源、识别版本和复核记录。

# 七、开源项目与技术复用建议

| 开源项目/技术 | 适合借鉴的能力 | 不应误认为 | 建议 |
| :--- | :--- | :--- | :--- |
| PDFMathTranslate | PDF翻译流程、版面保护、译文回填 | 完整专业图形重建平台 | 研究其文档处理和回填机制 |
| MinerU | PDF结构解析、版面、表格、公式和图片提取 | 开箱即用的所有专业识别能力 | 优先做真实PDF对照测试 |
| Marker | 多格式解析、结构化输出、混合解析思路 | 无配置即可在任意AI Studio环境运行 | 作为解析架构对照 |
| Pix2Text | 文档、公式、OCR识别 | 所有复杂公式均可准确识别 | 作为公式识别候选引擎 |
| WebPlotDigitizer | 曲线和图表数据数字化 | 完整工程曲线语义重建 | 针对少量性能曲线验证 |
| ezdxf | DXF 文件读取、修改和生成 | 扫描PDF工程图自动转CAD | 仅在真实DXF需求出现时引入 |

建议采用“复用优先、服务化按需、原图保真兜底”的路线。先验证引擎在当前运行环境中的可安装性、模型资源、依赖许可、执行时长、内存和真实输出，再决定是否集成。不得把 GitHub README 中的能力描述直接当作本项目已具备的能力。

## 7.1 许可和商业使用注意

引入开源项目时应核查具体版本、依赖树和许可证。AGPL、GPL、MIT、Apache-2.0 等许可证的义务不同；是否修改、分发、网络提供服务、是否与闭源模块组合，可能影响合规义务。正式商业化前应由法律专业人员核验，不应仅凭仓库首页标签判断。

# 八、研发路线与阶段验收建议

## 8.1 先验证需求，再扩展算法

| 阶段 | 目标 | 关键验证内容 | 阶段出口 |
| :--- | :--- | :--- | :--- |
| R0｜样本与环境盘点 | 确认真实业务文件和运行边界 | 文件类型、PDF类型、现有依赖、API、Word导出、环境限制 | 形成真实样本清单和能力盘点 |
| R1｜基础保真与表格 | 解决最常见的文件信息损失 | 原生文本、扫描件、表格、图像、坐标和输出 | 关键数据和表格可核对 |
| R2｜常见流程和工程图保真 | 支持常见工程图的定位、保留、图中文字处理 | 流程图、布局图、接线图、安装图 | 原图不变、文字区域可追踪 |
| R3｜曲线和图表专项 | 验证高价值曲线提取 | 坐标轴、刻度、图例、曲线、数据点 | 误差可量化，低质量图可回退原图 |
| R4｜公式专项 | 解决当前公式误检并验证结构重建 | 误检率、漏检率、重复框、边界偏移、LaTeX/OMML | 以真实公式页和非公式页验收 |
| R5｜跨文件与交付 | 服务完整业务资料包 | 术语一致、跨文档引用、Word/PDF、复核记录 | 形成可交付的业务文件包 |

## 8.2 第一轮真实样本建议

不建议一开始构建庞大的行业样本库。先收集 5 个真实资料包，每包 5—15 份文件或页面即可，优先覆盖设备进口、项目可研、制造业收购、工程安装、专业服务五类场景。样本需脱敏并获得合法使用授权。

| 资料包 | 优先文件 | 主要检验对象 |
| :--- | :--- | :--- |
| 设备进口包 | 说明书、规格书、报价技术附件、安装图、检验报告 | 参数表、型号、单位、安装图、接线图 |
| 工业项目包 | 可研技术章节、设备配置、总图、工艺方案、公用工程 | 流程图、布局图、设备表、能耗表 |
| 收购尽调包 | 资产台账、设备档案、维护记录、产能/质量报告 | 表格、趋势图、设备位号、跨文件一致性 |
| 工程安装包 | 施工规范、安装手册、平面/剖面/接线图、验收表 | 尺寸、单位、符号、图中文字、验收指标 |
| 服务机构包 | 标准规范、检测报告、客户技术附件、审查报告 | 多语言术语、引用、批量处理和交付 |

## 8.3 建议验收指标

| 指标 | 定义 | 初期验证方式 |
| :--- | :--- | :--- |
| 表格结构保留率 | 原表行列、合并关系、表头层级被正确保留的比例 | 抽取真实表格逐项核对 |
| 关键数值一致率 | 型号、参数、单位、数值、标准编号无误的比例 | 建立人工标注基准集 |
| 图形保真度 | 原图线条、位置、比例、符号和连接关系是否改变 | 原图与输出叠加/差异检查 |
| 图中文字定位准确率 | 译文对应到正确图中文字区域的比例 | 逐区域人工核对 |
| 公式误检/漏检率 | 非公式误报和真实公式漏报情况 | 同时测试目录、正文、公式页和表格页 |
| 可追溯率 | 输出对象可定位回原始页码和区域的比例 | 检查来源坐标和日志 |
| 真实任务完成率 | 真实资料包可成功完成解析、翻译和导出比例 | 禁止用模拟数据替代 |

首轮验收不宜先设一个脱离样本质量的统一高准确率承诺。应先建立人工标注基准，统计不同 PDF 来源、扫描质量、语言和对象类型的实际表现，再设定分层门槛。

# 九、商业价值判断与产品差异化

## 9.1 中小企业为什么可能需要它

* 专业翻译成本高：设备、工程、法律和检测文件通常需要懂专业内容的译者，而不是普通文本翻译。
* 资料分散：同一交易或项目可能同时涉及制造商、供应商、设计单位、政府部门、检测机构和投资方。
* 信息损失风险：PDF 转换、OCR、翻译和 Word 回填可能丢失表格、图形、数值或版面关系。
* 专业团队不足：中小企业往往没有专门的文档工程、术语管理和跨语言技术审查团队。
* 交易时效要求：投资决策、设备采购和尽调往往有较紧的资料审查窗口。

## 9.2 差异化不是模型数量

建议把竞争优势建立在五个方面：专业资料包工作流、跨标准术语与单位保护、原始对象保真、翻译结果可追溯、关键内容风险提示。单纯接入更多大模型并不能构成稳定的专业壁垒。

## 9.3 可能的产品交付形态

| 交付形态 | 适合用户 | 价值 |
| :--- | :--- | :--- |
| 单文件专业翻译 | 设备采购、工程技术人员 | 快速处理说明书、规格书和技术附件 |
| 批量资料包处理 | 投资方、收购方、项目公司 | 将可研、资产、设备、检测文件统一整理 |
| 双语审查版 | 工程承包商、咨询机构、律师/审计协作 | 便于原文对照、专业复核和合同附件使用 |
| 资料室索引与术语统一 | 收购、合资、长期项目 | 跨文件检索、统一设备名称和技术术语 |

# 十、结论与决策建议

1. GlobalCodeTrans 应定位为跨境专业技术文档翻译与保真处理平台，而不是全行业工程图自动重建平台。
2. 首期目标客户优先考虑设备贸易/进口商、工业项目投资方和制造业收购/合资方；工程承包商和专业服务机构作为扩展用户。
3. 首期文件优先级应是设备说明书、技术规格书、参数表、检验报告、可研技术附件、资产台账、维护记录和安装/接线图。
4. 首期信息对象优先级应是表格与参数、原文/版面保真、流程关系、图中文字定位翻译、常见设备图；曲线和公式作为专项能力逐步增强。
5. 复杂工程图首期采用原图保真、高清提取和图中文字处理，不承诺所有图纸自动结构重建。
6. 下一步不应立即扩充大批模块，而应先收集五类真实资料包，完成当前仓库和运行环境盘点，再决定具体引擎和开发顺序。

最终产品原则：以目标文件中实际存在的信息为唯一依据；能原生提取则不重新识别，能可靠结构化则重建，不能可靠重建则保留原图；不推测、不补造、不擅自改变技术信息。
